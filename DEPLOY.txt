FIN360 BACKEND — MANUAL DEPLOYMENT
Release 2.4.0
==============================================================================

What 2.4.0 adds and fixes (2 new database migrations, one of them changes data):
  * PRODUCT PRICES ARE CORRECTED BY THIS RELEASE. Read "PRODUCT PRICES" below
    before running step 6.
  * Invoice and bill line items can now be edited and saved. The change is
    posted to the accounts as a new adjusting entry and stock follows it.
    Items are locked once a payment or credit note exists.
  * Deleting an invoice or bill now reverses its journal entries. Bill
    payments can be voided; overpaying a bill is refused; a bill with
    payments can't be deleted or cancelled until they are voided.
  * Round off to the nearest rupee on quotations, proforma invoices and
    invoices, with its own Round Off line (accounts: 4900 Round Off, created
    automatically). Quotation and proforma round-off carries into the invoice.
  * The discount in rupees on a line is now taken off the price INCLUDING GST
    (650000 less 2500 = 647500). GST is then charged on the discounted value.
  * IGST, or CGST + SGST, is printed from the customer's state or GSTIN.
    Quotation totals read: Total, Special Discount, Sub Total, tax,
    Round Off, Net Amount, in every quotation design.
  * New command to tidy the accounts: see step 9.
  * Deploy this backend BEFORE the new frontend goes live (Cloudflare builds
    it as soon as it is pushed).

PRODUCT PRICES (read before step 6)
  Prices in the product list were entered with 5% GST already included, but
  invoices and quotations add GST on top of a product's price (650000 became
  682500). Migration 2026_11_04_000002 corrects this: EVERY product is set to
  5% GST and its price becomes price / 1.05 (650000 -> 619047.62, which shows
  as 650000.00 again with GST). Saved invoices and quotations are not changed.
    * Run it only if every product's current price includes 5% GST. Check
      first in phpMyAdmin:  select id, name, unit_price, tax_rate from products;
    * It saves the old prices to storage/app/backups/
      product-prices-before-gst-correction.csv and "php artisan
      migrate:rollback --step=1" puts them back from that file.
    * It runs once. To leave prices exactly as they are, mark it as done
      BEFORE step 6 with this SQL in phpMyAdmin (use the batch number of the
      last row of the migrations table):
        insert into migrations (migration, batch) values
          ('2026_11_04_000002_convert_product_prices_to_exclude_gst', 99);
    * A few products come back one paisa off when GST is added again (6190.49
      instead of 6190.48). That cannot be avoided with prices stored before GST.

What 2.3.0 fixes (no new database migrations):
  * Line discounts were subtracted twice on quotations, proformas and invoices.
    New documents are correct; see "CORRECT DOCUMENTS ALREADY SAVED" below for
    the old ones.
  * Lines now add up exactly to the totals. A line discount can't exceed the
    line's value.
  * Deploy this backend BEFORE relying on the new frontend: an older backend
    keeps subtracting discounts twice.

What 2.2.0 added:
  * Full-page letterhead: upload an A4 PDF or image once; invoices and
    quotations print on it, with proper page breaks.
  * New invoice templates "Full-page letterhead" and "Classic GST on
    letterhead"; new quotation design "Full-page letterhead".

What 2.1.0 added (on top of 2.0.0, the Lead CRM -> Fin360 conversion):
  * Invoices: part payments, credit notes, voiding payments/credit notes,
    "Classic GST" boxed invoice template, Ship To, UOM, custom fields.
  * Products: pictures, SKU/brand/model, feature lists, stock tracking
    (invoices deduct stock automatically).
  * Quotations: letterhead design with your own header/footer artwork,
    product pictures and an editable Terms & Conditions page.

If the server is still on the old Lead CRM version, this one release takes
it straight to 2.4.0 — follow every step below.

Package:  fin360-backend-2.4.0.zip
Server:   cPanel, PHP 8.1+ (production runs 8.1), MySQL 5.7+ / MariaDB 10.4+
Layout:   the document root is the PROJECT ROOT (the folder containing .env,
          artisan, app/, public/). The root index.php + .htaccess forward
          requests into public/.

The zip contains the full application with production dependencies (vendor/,
composer --no-dev). It does NOT contain .env or any uploaded files
(storage/app/public: logos, seals), so extracting it over the live folder
keeps your configuration and uploads.

Time needed: about 15 minutes. Do it outside office hours if possible.


------------------------------------------------------------------------------
0. SECURITY CHECK FIRST (2 minutes)
------------------------------------------------------------------------------
The old root .htaccess did not block direct access to files such as .env.
Before updating, open this in a private browser window:

    https://leadcrm.peoplenex.online/.env

  * If you get "403 Forbidden" or "404 Not Found": fine, continue.
  * If the file downloads or its text shows: it was publicly readable.
    After this deployment (which blocks it), change the database password
    in cPanel > MySQL Databases and update DB_PASSWORD in .env, and change
    MAIL_PASSWORD if one is set. Also check https://leadcrm.peoplenex.online/storage/logs/laravel.log
    the same way.

8. CORRECT DOCUMENTS ALREADY SAVED (needs Terminal)
------------------------------------------------------------------------------
Documents saved before 2.3.0 with a line discount have the discount taken off
twice. Take the database backup from step 1 first if you skipped it, then:

  a) List them. This changes nothing:

       php artisan fin360:repair-double-discounts

  b) Correct quotations and proforma invoices (no effect on the accounts):

       php artisan fin360:repair-double-discounts --apply

  c) Invoices raise what the customer owes, and the customer has already seen
     the lower figure, so decide this one deliberately. To correct UNPAID
     invoices and post an adjusting journal entry (JE-ADJ-INV-…):

       php artisan fin360:repair-double-discounts --apply --invoices

Invoices with payments or credit notes are never changed. They show as
"REVIEW BY HAND"; settle those with the customer and correct them manually.

Afterwards the list command should say "No affected documents found", apart
from any invoices you chose to leave or review by hand.


------------------------------------------------------------------------------
9. CLEAN UP DELETED INVOICES AND BILLS (needs Terminal)
------------------------------------------------------------------------------
Before 2.4.0, deleting an invoice or bill left its journal entries in the
accounts, so Accounts Receivable / Payable still counted it. Take the backup
from step 1 first, then:

  a) List them. This changes nothing:

       php artisan fin360:repair-deleted-documents

  b) Reverse the entries of deleted documents that have no payments or credit
     notes:

       php artisan fin360:repair-deleted-documents --apply

Deleted documents that HAD payments or credit notes are only listed ("REVIEW BY
HAND"). The money may really have moved; decide each one with the customer
or vendor, because reversing only the sale would leave the accounts wrong the
other way. Running the command again changes nothing further.

WHAT THE MIGRATIONS CHANGE IN THE DATABASE
------------------------------------------------------------------------------
1. remove_crm_permissions
   Deletes the Lead CRM permission definitions (leads, follow-ups, call logs,
   notes, CRM customers, lead sources/statuses) and their role/user grants.
   CRM DATA TABLES ARE NOT TOUCHED (leads, followups, ...). Drop them later
   yourself once archived.

2. make_accounting_settings_company_wide
   Business & tax details (letterhead), accounting preferences, numbering
   and the invoice template were stored per user; most copies were blank.
   One company-wide row is created from the most complete profile (on the
   current data: Sruthi's — GSTIN 32BGKPA0180J1ZT). That user's old row is
   kept as history; every other user's copy is DELETED.

3. add_layout_to_invoice_template_settings
   Adds a JSON column for the invoice template builder. No data changes.

4. add_print_fields_to_invoices
   Adds Ship To and custom-field values to invoices, a unit (UOM) to invoice
   lines, and contact person / PAN to customers. No data changes.

5. add_catalog_and_stock_to_products
   Adds picture, SKU, brand, model, features, purchase price and stock
   fields to products, and a stock movements table. Existing products start
   with stock tracking OFF, so nothing is deducted until you turn it on.

6. add_credit_notes_and_payment_accounts
   Adds invoices.amount_credited, the deposit bank account on payments, and
   date/subtotal/tax/reason to credit notes. Existing payments are untouched;
   existing invoices start with 0 credited.

7. add_round_off_to_documents
   Adds round_off (default 0) to quotations, proforma_invoices and invoices.
   Existing documents keep their totals and show no Round Off line.

8. convert_product_prices_to_exclude_gst   (changes data - see PRODUCT PRICES)
   Sets every product to 5% GST and divides its price by 1.05. The old prices
   are saved to storage/app/backups/product-prices-before-gst-correction.csv
   first; rolling this migration back restores them.

The roles seeder adds the Finance Manager, Accountant and Viewer roles and
refreshes the Super Admin / Admin permission lists. Existing roles and users
keep their assignments.

Behaviour changes users may notice:
  * Only users with the "Accounting Settings" permission (admins) can change
    company details, the invoice template and payment methods. Accountants
    could before.
  * Everyone who can view invoices/quotations sees the same letterhead.
  * The CRM screens and endpoints are gone.
  * An invoice becomes "Paid" by recording payments / credit notes; it can
    no longer be marked paid by hand while money is outstanding.
  * An invoice with payments or credit notes can't be deleted until they
    are voided. The same applies to a bill with payments.
  * An invoice or bill with payments can't have its items edited. A paid or
    cancelled one can't either.
  * The discount in rupees is off the price with GST (see above).

ROLLBACK
------------------------------------------------------------------------------
  1. php artisan down (if available)
  2. Restore the files backup from step 1b over the backend folder.
  3. phpMyAdmin > the database > Import > the .sql backup from step 1a.
  4. php artisan optimize:clear && php artisan up

FRONTEND (Cloudflare Pages)

    Build command:          npm run build
    Build output directory: dist
    Environment variable:   VITE_API_BASE_URL = https://leadcrm.peoplenex.online/api
